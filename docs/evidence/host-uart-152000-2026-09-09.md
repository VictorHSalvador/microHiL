# Evidência HOST — UART 152.000 bit/s

Data: 09.09.2026  
Ambiente: Ubuntu 22.04.5 x86-64; GCC 11.4.0; kernel 6.8.0-138-generic; build isolado em `/tmp/microhil-uart152`.

## Procedimento executado

1. Configurar o projeto sem o runner FMU, com `BUILD_TESTING=ON`.
2. Compilar os componentes HOST e os testes.
3. Executar `ctest --test-dir /tmp/microhil-uart152 --output-on-failure`.
4. Em `daq_tty_validation`, abrir um pseudo-terminal Linux, aplicar UART 8N1 sem RTS/CTS pela API `termios2` com `BOTHER`, e consultar a taxa configurada com `TCGETS2`.
5. Em `daq_protocol_xrce_mtu`, aceitar payload XRCE de 128 bytes e rejeitar 129 bytes.

## Resultado observado

O build concluiu e o CTest executou 39 testes com sucesso. O teste TTY observou `c_ispeed=152000` e `c_ospeed=152000` no pseudo-terminal. O codec aceitou o MTU XRCE selecionado de 128 bytes e rejeitou payload acima dele. O coordenador exige esse MTU em sua configuração.

## Limites

Pseudo-terminal não exerce o driver CH340, a UART física, o ESP32, micro-ROS, o Agent, a FMU ou qualquer medição de deadline. O resultado comprova somente que a implementação HOST Linux pede e lê de volta 152.000 bit/s por `termios2`; não comprova taxa efetiva, erro de baud, integridade de dados ou orçamento temporal no enlace CH340–ESP32.
