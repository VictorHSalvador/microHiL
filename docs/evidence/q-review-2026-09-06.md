- Serviço aponta ao launcher, que seleciona raspdaq_main. Main cria SharedDaqState uma vez e injeta a mesma instância no runtime USB e nó ROS. SharedDaqState mantém snapshots frozen/slots e troca referências sob RLock. Não há recriação do nó a cada snapshot.
- FunctionFS possui ep0 e endpoints bulk ep1/ep2 no Linux dispositivo. O protocolo observado usa SYNC 0xAA55, little-endian, MIDs CONFIG=01/HIL_TO_DAQ=02/DAQ_TO_HIL=03, cabeçalho DATA com SEQ de 2 bytes e payload 251 para frame 256. Comandos e STATUS diferem do MICROHIL. São dados de referência, não valores adotados.
- O controle atende CONFIG em streaming; STOP_STREAM limpa estado na referência. MICROHIL exige retenção em Stop, então essa limpeza não deve ser copiada. Prints incondicionais e alocações Python também não são contratos aceitáveis para a thread C crítica.
- Q-03/Q-04/Q-08 resolvidas; subitens restantes das outras Q discriminados em decisions. Novo F-27 registra ausência do host; tempos continuam pendentes.
- Verificação estrutural executada: 59 IDs únicos (F-01…27 e NF-01…32), cada um com critério V correspondente, design, tarefa e pendência; matriz contém exatamente os mesmos 59 IDs. Resultado: aprovado somente nesse escopo documental.
- Referências recebidas comparadas byte a byte com Downloads: idênticas. Não foram atualizadas para incorporar decisões novas.

## Fontes técnicas consultadas

- [Schema ScalarVariable FMI 2.0.4](https://raw.githubusercontent.com/modelica/fmi-standard/v2.0.4/schema/fmi2ScalarVariable.xsd): valueReference identifica acesso FMI e não é necessariamente único; não tratar como posição do registro.
- [FunctionFS, kernel Linux](https://docs.kernel.org/usb/functionfs.html): função USB em espaço de usuário no lado gadget Linux; não camada de dispositivo ESP32.
- [pthread_setschedparam, Linux man-pages](https://man7.org/linux/man-pages/man3/pthread_setschedparam.3.html): pode falhar por permissões; verificar configuração real. Nenhuma política foi alterada no host.
